# ADR-001: Build on Cloudflare Workers + D1 + static page (GitHub Pages or Worker assets)

Status: accepted  
Date: 2026-11-12

## Context
A graduating student cannot tell which skills employers for a target role actually ask for. The system must show missing skills ordered by how often they appear in a fixed set of postings. Live job data is paid or restricted; the course stack is Cloudflare Workers + D1; every team member has already deployed on it.

## The Gate
Build (Cloudflare Worker + D1 + static page) scored highest on fit and team capability in the Phase 1 Gate. Buy (existing job boards) does not answer the actual question. Delegate (bolt.new hosts everything) produced unmaintainable output in earlier probes.

## Options considered
| Option | For | Against |
|--------|-----|---------|
| Build on Workers + D1 | Team already knows it, free tier sufficient for the course, full control of data, easy export | Frozen synthetic data, free-tier daily limits |
| Buy existing product | Faster | None answer “given my skills, what should I learn next” |
| Delegate fully to bolt.new | Very fast first version | High switching cost, hidden dependencies, hard to own |

## Decision
Build a single Cloudflare Worker that serves the static page (or pair with GitHub Pages) and queries a D1 database of synthetic postings. Student skills stay request-scoped and are never stored. No external model call in the initial architecture.

## Consequences
- Data is a frozen synthetic snapshot (limitation accepted).
- Free-tier daily request and D1 row limits apply; we stay well under them for course use.
- Exit path exists (`wrangler d1 export` + rewrite the single Worker file).
- Reversal trigger: free-tier limits become binding, Cloudflare changes terms, or we need real live postings.
